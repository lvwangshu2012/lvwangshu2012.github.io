    Tarjan 算法与无向图连通性（割点与桥）¶

    参考资料

    • 李煜东《算法竞赛进阶指南》，0x66 Tarjan 算法与无向图连通性
    • OI Wiki：割点和桥
    • OI Wiki：图论相关概念
    • OI Wiki：双连通分量
    • Robert Tarjan, Depth-First Search and Linear Graph Algorithms, SIAM J. Comput., 1972

    1 割点与桥的定义¶

    1.1 基本定义¶

    给定无向连通图 \(G = (V, E)\)：

    概念 定义
    割点（割顶） 若对于 \(x \in V\)，从图中删去节点 \(x\) 以及所有与 \(x\) 关联的边之后，\(G\) 分裂成两个或两个以上不相连的子图，则称 \(x\) 为 \(G\) 的割点
    桥（割边） 若对于 \(e \in E\)，从图中删去 \(e\) 之后，\(G\) 分裂成两个不相连的子图，则称 \(e\) 为 \(G\) 的桥

    更严谨的说法（OI Wiki）：删去后使图的极大连通分量数增加的点 / 边，就是割点 / 桥。

    1.2 一般（非连通）无向图¶

    对于一般无向图（不一定连通），它的"割点"和"桥"就是它的各个连通块的"割点"和"桥"。

    实现含义：必须对每一个尚未访问的节点都跑一次 Tarjan（得到搜索森林），而不是只从一个点出发。

    1.3 关于 Tarjan 算法¶

    以著名计算机科学家 Robert Tarjan 命名的 Tarjan 算法，能够在线性时间内求出无向图的割点与桥，进一步可求出无向图的双连通分量（本节后半部分介绍）。在有向图方面，Tarjan 算法能够求出强连通分量、必经点与必经边（下一节介绍）。

    Tarjan 在数据结构方面同样贡献卓著：证明了并查集的时间复杂度，提出了斐波那契堆、Splay Tree 和 Link-Cut Tree 等。

    2 深度优先遍历的两个基础量¶

    Tarjan 算法基于无向图的深度优先遍历。

    2.1 时间戳 \(dfn\)¶

    在图的深度优先遍历过程中，按照每个节点第一次被访问的时间顺序，依次给予 \(N\) 个节点 \(1 \sim N\) 的整数标记，该标记称为时间戳，记为 \(dfn[x]\)。

    2.2 搜索树与搜索森林¶

    在无向连通图中任选一个节点出发进行深度优先遍历，每个点只访问一次。所有发生递归的边 \((x, y)\)（换言之，从 \(x\) 到 \(y\) 是对 \(y\) 的第一次访问）构成一棵树，称为无向连通图的搜索树。

    一般无向图（不一定连通）的各个连通块的搜索树共同构成无向图的搜索森林。

    2.3 无向图 DFS 的关键性质¶

    在无向图的深度优先遍历中，任意一条边 \((x, y)\) 只有两种身份：

    1. 树边：\(x\) 与 \(y\) 在搜索树上是父子关系；
    2. 非树边（回边）：\(x\) 与 \(y\) 在搜索树上是祖先与后代的关系。

    这与有向图不同：无向图的 DFS 不存在横叉边。因为在无向图中，若 \((x,y)\) 存在且 \(x\) 先被访问，那么在处理 \(x\) 时 \(y\) 必然会被递归访问（成为树边）或已经被访问（成为回边），不可能出现"两个子树之间的横向连接"。

    由此立刻得到两条重要推论（它们正是 §4 判定法则的基础）：

    • 推论 1：桥一定是搜索树中的边——非树边 \((x,y)\) 与其两端的树上路径一起构成一个环，环上的边都不可能是桥。
    • 推论 2：一个简单环中的边一定都不是桥——删去环上任一条边后，环上其余边仍把两端连通。

    3 追溯值 \(low\)¶

    3.1 定义¶

    Tarjan 算法引入追溯值 \(low[x]\)。设 \(subtree(x)\) 表示搜索树中以 \(x\) 为根的子树，\(low[x]\) 定义为以下节点的时间戳的最小值：

    1. \(subtree(x)\) 中的节点；
    2. 通过 1 条不在搜索树上的边，能够到达 \(subtree(x)\) 的节点。

    3.2 等价化简¶

    由于 \(x\) 是 \(subtree(x)\) 中时间戳最小的节点（子树内所有点都在 \(x\) 之后才被访问），第 1 类节点的最小值就是 \(dfn[x]\) 本身。所以

    \(\boxed{low[x] = \min\Big(\,dfn[x],\ \min\{\,dfn[z] \mid \text{存在一条非树边从 } subtree(x) \text{ 内的点连到 } z \,\}\Big)}\)

    \(low[x]\) 的直观含义是：从 \(subtree(x)\) 出发，只许用至多 1 条非树边，能够回溯到的最高（最早）的祖先。

    3.3 计算方法¶

    先令 \(low[x] = dfn[x]\)，然后考虑从 \(x\) 出发的每条边 \((x, y)\)：

    边 \((x,y)\) 的身份 更新方式 理由
    树边，且 \(x\) 是 \(y\) 的父节点 \(low[x] = \min(low[x],\ low[y])\) \(subtree(y) \subseteq subtree(x)\)，子树内已算好的追溯值可以整体继承
    非树边 \(low[x] = \min(low[x],\ dfn[y])\) 只能用这一条非树边，故取的是 \(dfn[y]\)

    3.4 为什么非树边必须用 \(dfn[y]\) 而不是 \(low[y]\)¶

    因为 \(low\) 的定义限定为"1 条不在搜索树上的边"。从 \(x\) 沿非树边走到 \(y\)，这一步能获得的只有 \(dfn[y]\)；而 \(low[y] \le dfn[y]\) 是 \(subtree(y)\) 通过它自己的非树边回溯的结果，那相当于"走了两步"（先沿树边下到 \(y\)，再用 \(y\) 的非树边），不属于从 \(x\) 出发一次可达的范围。

    若误用 \(low[y]\)，会让 \(low[x]\) 偏小，从而漏判割点与桥。

    附注：在无向图 DFS 中，从 \(x\) 扫描到的已访问节点 \(y\) 必为 \(x\) 的祖先，不可能是后代——后代只会在树边分支中出现（见 §2.3）。

    4 桥（割边）判定法则¶

    4.1 判定法则¶

    无向边 \((x, y)\) 是桥，当且仅当它在搜索树上是一条父子边（设 \(x\) 是 \(y\) 的父节点），并且满足

    \(\boxed{dfn[x] < low[y]}\)

    4.2 正确性证明¶

    充分性（满足该式 \(\Rightarrow\) 是桥）

    \(dfn[x] < low[y]\) 说明：从 \(subtree(y)\) 出发，在不经过 \((x,y)\) 的前提下，不管走哪条边，都无法到达 \(x\)，也无法到达比 \(x\) 更早访问的节点。此时若把 \((x,y)\) 删除，\(subtree(y)\) 就好像形成了一个封闭的环境，与节点 \(x\) 没有任何边相连，图被断成两部分，因此 \((x,y)\) 是割边。

    必要性（不是桥 \(\Rightarrow\) 不满足该式）

    反之，若不存在这样的子节点 \(y\) 使得 \(dfn[x] < low[y]\)，即对每个子节点 \(y\) 都有 \(low[y] \le dfn[x]\)，则说明每个 \(subtree(y)\) 都能绕行其他边到达 \(x\) 或比 \(x\) 更早访问的节点。删去 \((x,y)\) 后，\(subtree(y)\) 仍可通过这条绕行路径与上方连通，\((x,y)\) 自然就不是割边。

    4.3 为什么是严格不等号¶

    情形 含义 结论
    \(low[y] > dfn[x]\) \(subtree(y)\) 连 \(x\) 自己都回不去，\((x,y)\) 是唯一的连接通道 是桥
    \(low[y] = dfn[x]\) \(subtree(y)\) 能回到 \(x\)（例如存在另一条连到 \(x\) 的边），删掉 \((x,y)\) 后仍连通 不是桥

    这正是桥判定用 \(>\)、而 §7 割点判定用 \(\ge\) 的根本原因。

    4.4 两条推论¶

    由 §2.3 的无向图 DFS 性质直接得到：

    1. 桥一定是搜索树中的边——非树边必在某个环上。
    2. 一个简单环中的边一定都不是桥。

    5 重边陷阱与「成对变换」¶

    5.1 朴素"记录父节点"写法的漏洞¶

    因为我们遍历的是无向图，每条边存了两遍，所以从每个点 \(x\) 出发，总能访问到它的父节点 \(fa\)。根据 \(low\) 的计算方法，\((x, fa)\) 属于搜索树上的边，且 \(fa\) 是 \(x\) 的父节点，故不能用 \(fa\) 的时间戳来更新 \(low[x]\)。

    于是常见的朴素写法是：

    if (v != fa) low[u] = min(low[u], dfn[v]);   // 跳过父节点

    这个写法在无重边时是正确的，但有重边时会出错。

    考虑 \(x\) 与 \(fa\) 之间有 \(k \ge 2\) 条边的情形：此时 \((x, fa)\) 一定不是桥（删掉其中一条，还有别的边连着）。在这 \(k\) 条重复的边中，只有一条算是"搜索树上的边"，其余 \(k-1\) 条都不算，它们都是合法的非树边，应当用 \(dfn[fa]\) 去更新 \(low[x]\)。

    而 v != fa 的判断会把这 \(k\) 条边全部跳过，导致 \(low[x]\) 偏大，从而把 \((x, fa)\) 误判成桥。

    5.2 解决方案：记录"进入该节点的边的编号"¶

    一个好的解决方案是：把递归参数由「父节点编号」改为「递归进入该节点的边的编号」。编号可认为是边在邻接表中存储的下标位置。

    在 0x01 和 0x13 节提到过成对变换技巧：把无向图的每一条边看作双向边，成对存储在下标"2 和 3""4 和 5""6 和 7"… 处（即下标从 \(2\) 开始，一条无向边的两个方向分别占 \(i\) 与 \(i \oplus 1\)）。

    于是：

    若沿着编号为 \(i\) 的边递归进入了节点 \(x\)，则只忽略从 \(x\) 出发的编号为 \(i \oplus 1\)（即 i ^ 1）的那一条边，其余所有边（包括与父节点之间的重边）都正常参与计算 \(low[x]\)。

    这样做精确地把"树边的反向边"排除掉，而重边作为独立编号的边自然会被保留，问题彻底解决。

    5.3 割点是否也需要边编号写法¶

    结论：求割点时，用 v != fa 跳过父节点的写法在有重边时依然是正确的（不会误判）；但求桥时必须用边编号（或等价的标记法）。

    理由：割点的判定用的是非严格不等式 \(low[y] \ge dfn[x]\)。设真实追溯值为 \(low^*[y]\)，朴素的 v != fa 写法得到的值是 \(low'[y] \ge low^*[y]\)（少了一些更新，只会偏大不会偏小）。

    • 若 \(x\) 真实不是割点，则对每个子节点 \(y\) 有 \(low^*[y] < dfn[x]\)，意味着 \(subtree(y)\) 中存在一条非树边连到某个 \(w\) 且 \(dfn[w] < dfn[x]\)。由于 \(dfn[w] < dfn[x]\)，\(w\) 绝不可能是 \(y\) 的父节点 \(x\)，因此这条边不会被 v != fa 跳过，于是 \(low'[y] \le dfn[w] < dfn[x]\)，判定结果一致。
    • 唯一可能被"吞掉"的更新是连回 \(x\) 本身的那些重边，它们只会让 \(low^*[y]\) 恰好等于 \(dfn[x]\)；而不论取 \(dfn[x]\) 还是取更大的 \(dfn[y]\)，都满足 \(\ge dfn[x]\)，结论相同。

    而桥的判定是严格不等式 \(dfn[x] < low[y]\)：重边本应让 \(low[y] = dfn[x]\)（从而判为"非桥"），朴素写法却得到 \(low[y] = dfn[y] > dfn[x]\)（判为"桥"），产生误判。

    注：统一采用"记录边的编号 + 成对变换"的写法，同一份代码既能安全求桥也能安全求割点，不必区分场景。

    6 求桥的参考程序¶

    6.1 代码¶

    链式前向星存图，成对变换，编号从 \(2\) 开始（tot 初始化为 \(1\)）。

    #include <bits/stdc++.h>
using namespace std;

const int SIZE = 100010;
int head[SIZE], ver[SIZE * 2], Next[SIZE * 2];
int dfn[SIZE], low[SIZE], n, m, tot, num;
bool bridge[SIZE * 2];

void add(int x, int y) {
    ver[++tot] = y, Next[tot] = head[x], head[x] = tot;
}

void tarjan(int x, int in_edge) {
    dfn[x] = low[x] = ++num;                 // 第一次访问 x，打时间戳
    for (int i = head[x]; i; i = Next[i]) {
        int y = ver[i];
        if (!dfn[y]) {                       // (x, y) 是搜索树上的边
            tarjan(y, i);                    // 记录递归进入 y 的边编号 i
            low[x] = min(low[x], low[y]);    // 树边：用子树的 low 更新

            if (low[y] > dfn[x])             // 割边判定法则
                bridge[i] = bridge[i ^ 1] = true;   // 标记两个方向
        }
        else if (i != (in_edge ^ 1))         // 非树边：只排除"来时那条边的反向边"
            low[x] = min(low[x], dfn[y]);    // 注意是 dfn[y]，不是 low[y]
    }
}

int main() {
    scanf("%d%d", &n, &m);
    tot = 1;                                 // 成对变换：边编号从 2 开始，(2,3)(4,5)... 成对
    for (int i = 1; i <= m; i++) {
        int x, y;
        scanf("%d%d", &x, &y);
        add(x, y), add(y, x);
    }
    for (int i = 1; i <= n; i++)             // 图不一定连通：搜索森林
        if (!dfn[i]) tarjan(i, 0);           // 根节点没有"来时的边"，传 0（0^1=1，不是合法边号）

    for (int i = 2; i < tot; i += 2)         // 每条无向边只输出一次
        if (bridge[i])
            printf("%d %d\n", ver[i ^ 1], ver[i]);   // 还原该边的两个端点
}

    6.2 代码要点说明¶

    位置 说明
    tot = 1 保证第一条边占用下标 \(2,3\)，第二条占 \(4,5\)，…，使 \(i \oplus 1\) 恰好指向同一条无向边的另一个方向
    tarjan(y, i) 把"递归进入 \(y\) 所用的边编号"传下去，而不是传父节点编号
    i != (in_edge ^ 1) 只忽略来时那条边的反向边；与父节点之间的重边编号不同，会被正常处理
    bridge[i] = bridge[i ^ 1] = true 无向边的两个方向都标记，避免后续漏查
    low[x] = min(low[x], dfn[y]) 非树边只用 \(dfn[y]\) 更新（见 §3.4）
    tarjan(i, 0) 根节点没有入边；\(0 \oplus 1 = 1\)，而合法边编号从 \(2\) 起，故不会误屏蔽任何边
    for (i = 2; i < tot; i += 2) 只枚举每条无向边的"正向"下标，避免同一条桥输出两次
    printf("%d %d", ver[i^1], ver[i]) \(i\) 存的是 \(x \to y\)，\(i \oplus 1\) 存的是 \(y \to x\)，故输出 ver[i^1]（即 \(x\)）与 ver[i]（即 \(y\)）

    7 割点判定法则¶

    7.1 判定法则¶

    设 \(x\) 是搜索树上的一个节点，\(y\) 是它在搜索树上的子节点。

    • 非根节点：\(x\) 是割点，当且仅当存在一个子节点 \(y\) 满足

    \(\boxed{low[y] \ge dfn[x]}\)

    • 根节点（每个连通块 DFS 的起点）：\(x\) 是割点，当且仅当它在搜索树中至少有两个子节点。

    7.2 为什么非根节点用 \(\ge\)¶

    \(low[y] \ge dfn[x]\) 表示：\(subtree(y)\) 最多只能回溯到 \(x\) 自己，到不了 \(x\) 的任何祖先。于是删去 \(x\) 及其所有关联边后，\(subtree(y)\) 就与图的其余部分彻底断开了，故 \(x\) 是割点。

    边界情形 \(low[y] = dfn[x]\) 表示"能回到 \(x\)，但回不到 \(x\) 上面"——删掉 \(x\) 之后这条回路也就断了，所以仍然是割点。这就是与桥判定（严格 \(>\)）的唯一差别。

    7.3 为什么根节点要特判¶

    根节点 \(x\) 没有祖先，条件"\(low[y] \ge dfn[x]\)"对它几乎总是成立（因为 \(dfn[x]\) 是最小的时间戳，\(low[y]\) 不可能小于它），于是"删去 \(x\) 后 \(subtree(y)\) 断开了"这一推理不再成立：根被删掉后，剩下的各棵子树之间本来就互不相连（无向图 DFS 不存在横叉边），与删根之前的状态相比没有变化。

    真正决定根是否为割点的是子树的棵数：

    • 若根只有 \(1\) 个子树，删掉根后剩下的仍是一整块，连通分量数不变 → 不是割点；
    • 若根有 \(\ge 2\) 个子树，删掉根后这些子树彼此断开，连通分量数增加 → 是割点。

    形象地理解：从起始点只"向下搜了一次"，说明其余点都能通过别的路径被抵达；若在搜索树内有两个及以上儿子，那么删掉它，各儿子子树之间就再无通路。

    7.4 与桥判定的对照¶

    项目 割点 桥
    判定式 \(low[y] \ge dfn[x]\) \(dfn[x] < low[y]\)（即 \(low[y] > dfn[x]\)）
    不等号 非严格（\(\ge\)） 严格（\(>\)）
    根节点 需要特判（子树个数 \(\ge 2\)） 不需要特判
    判定对象 节点 \(x\) 树边 \((x, y)\)
    相等情形 \(low[y] = dfn[x]\) 是割点 不是桥

    8 求割点的参考程序¶

    8.1 代码¶

    同样采用「记录边编号 + 成对变换」的稳妥写法。

    #include <bits/stdc++.h>
using namespace std;

const int SIZE = 100010;
int head[SIZE], ver[SIZE * 2], Next[SIZE * 2];
int dfn[SIZE], low[SIZE], n, m, tot, num;
bool cut[SIZE];

void add(int x, int y) {
    ver[++tot] = y, Next[tot] = head[x], head[x] = tot;
}

void tarjan(int x, int in_edge) {
    dfn[x] = low[x] = ++num;
    int child = 0;                           // 搜索树上的子节点个数
    for (int i = head[x]; i; i = Next[i]) {
        int y = ver[i];
        if (!dfn[y]) {
            child++;
            tarjan(y, i);
            low[x] = min(low[x], low[y]);

            if (low[y] >= dfn[x] && in_edge) // 非根节点：割点判定法则
                cut[x] = true;               // 根节点留到循环结束后统一判定
        }
        else if (i != (in_edge ^ 1))
            low[x] = min(low[x], dfn[y]);
    }
    if (!in_edge && child >= 2)              // 根节点：至少两个子树才是割点
        cut[x] = true;
}

int main() {
    scanf("%d%d", &n, &m);
    tot = 1;
    for (int i = 1; i <= m; i++) {
        int x, y;
        scanf("%d%d", &x, &y);
        add(x, y), add(y, x);
    }
    for (int i = 1; i <= n; i++)
        if (!dfn[i]) tarjan(i, 0);           // in_edge = 0 表示这是搜索树的根

    int cnt = 0;
    for (int i = 1; i <= n; i++) if (cut[i]) cnt++;
    printf("%d\n", cnt);
    for (int i = 1; i <= n; i++) if (cut[i]) printf("%d ", i);
}

    8.2 补充说明¶

    关于 in_edge 判根的写法：in_edge = 0 当且仅当 \(x\) 是某个连通块 DFS 的起点（根）。同时 \(0 \oplus 1 = 1\)，而边编号从 \(2\) 起，所以 i != (in_edge ^ 1) 在根节点处恒为真，不会误屏蔽任何边——两个用途高度自洽。

    另一种判根的写法（OI Wiki 上的常见形式）：把根也按 \(low[y] \ge dfn[x]\) 计入，最后若子树数 \(< 2\) 再把根取消标记。两种写法等价。

    9 复杂度与工程细节¶

    9.1 复杂度¶

    项目 量级 说明
    时间复杂度 \(O(N + M)\) 每个节点被访问一次，每条（有向）边被扫描常数次
    空间复杂度 \(O(N + M)\) 链式前向星存 \(2M\) 条有向边
    递归深度 \(O(N)\) 链状图时递归深度可达 \(N\)

    9.2 工程细节¶

    1. 非连通图：必须遍历 \(i = 1 \sim N\)，对每个 \(dfn[i] = 0\) 的点调用 tarjan(i, 0)，否则会漏掉其他连通块。
    2. 爆栈：\(N\) 达到 \(10^5 \sim 10^6\) 的链状数据时递归可能爆栈。对策：编译时开大栈（-Wl,--stack=...），或改写成手工栈的非递归 DFS。
    3. 数组规模：无向边存两遍，ver / Next / bridge 需开到 \(2M\)（常写成 SIZE * 2，需保证 \(M\) 不超过 SIZE）。
    4. 自环：自环 \((x, x)\) 会存成两条有向边，用边编号写法时 i != (in_edge ^ 1) 的判断依然正确；自环对 \(low\) 无影响（\(low[x] \le dfn[x]\) 恒成立），也永远不是桥。
    5. 输出去重：桥按无向边计数，遍历时只枚举偶数（或只枚举 \(i < i \oplus 1\) 的）下标。

    10 常见误区清单¶

    # 误区 正确做法
    1 用 v != fa 跳过父节点来处理非树边 有重边时会把 \((x, fa)\) 误判成桥。应记录边的编号，只跳过 in_edge ^ 1
    2 非树边用 low[y] 更新 \(low[x]\) 必须用 dfn[y]；low 的定义只允许1 条非树边
    3 桥判定写成 low[y] >= dfn[x] 桥必须用严格大于：low[y] > dfn[x]
    4 割点判定写成 low[y] > dfn[x] 割点必须用非严格：low[y] >= dfn[x]
    5 忘记对 DFS 根节点做割点特判 根是割点 \(\iff\) 搜索树中子树数 \(\ge 2\)
    6 只从一个起点 DFS 图不一定连通，需对所有 \(dfn = 0\) 的点各跑一次（搜索森林）
    7 桥只标记 bridge[i] 应 bridge[i] = bridge[i ^ 1] = true，两个方向都标记
    8 认为桥可能是非树边 非树边必在某个环上，桥一定是树边
    9 tot 从 \(0\) 开始 成对变换要求编号从 \(2\) 开始，tot 初始化为 \(1\)
    10 求桥时也套用割点的"根特判" 桥判定与是否为根无关，不需要特判

    11 小结¶

    1. 两个基石：时间戳 \(dfn\)（第一次访问的顺序）与追溯值 \(low\)（子树加至多一条非树边能回溯到的最早祖先）。
    2. 两条判定法则： - 桥：\(dfn[x] < low[y]\)（严格）； - 割点：\(low[y] \ge dfn[x]\)（非严格），根节点另需子树数 \(\ge 2\)。
    3. 最大的坑是重边：一律使用「记录进入该节点的边编号 + 成对变换 i ^ 1」的写法。

    后续内容：以下 §12–§15 在此框架上介绍无向图的双连通分量（边双连通分量 e-DCC 与点双连通分量 v-DCC），核心正是「把所有桥删掉」与「用栈维护 DFS 树上的点双」；至于有向图的强连通分量、必经点与必经边，见 图论：LCA、树的直径、树的重心、二分图与 Tarjan 缩点 一文。

    12 无向图的双连通分量¶

    12.1 定义¶

    若一张无向连通图不存在割点，则称它为点双连通图；若一张无向连通图不存在桥，则称它为边双连通图。

    • 无向连通图的极大点双连通子图被称为点双连通分量，简记为 v-DCC（vertex double connected component）。
    • 无向连通图的极大边双连通子图被称为边双连通分量，简记为 e-DCC（edge double connected component）。
    • 二者统称为双连通分量，简记为 DCC。

    其中"极大"是指：不存在包含 \(G'\) 的更大的子图 \(G'' = (V'', E'')\)，满足 \(V' \subseteq V'' \subseteq V\)、\(E' \subseteq E'' \subseteq E\)，并且 \(G''\) 也是双连通子图。

    等价的两点连通性表述（OI Wiki）：在连通无向图中，若无论删去哪条边（只能删一条）都不能使 \(u, v\) 不连通，则称 \(u, v\) 边双连通；若无论删去哪个点（只能删一个，且不能删 \(u, v\) 自身）都不能使它们不连通，则称 \(u, v\) 点双连通。

    由此可注意两条性质：

    • 边双连通具有传递性：\(x, y\) 边双连通且 \(y, z\) 边双连通 \(\Rightarrow\) \(x, z\) 边双连通。
    • 点双连通不具有传递性：两个三角形共用一个点 \(B\) 时，\(A, B\) 点双连通、\(B, C\) 点双连通，但 \(A, C\) 不点双连通。

    12.2 关键性质与易误解点¶

    1. v-DCC \(\neq\) "删去割点后图中剩余的连通块"。这是极易混淆的一点，请格外留意。
    2. 若某个节点为孤立点，则它自己单独构成一个 v-DCC；除孤立点外，v-DCC 的大小至少为 \(2\)。
    3. 桥不属于任何 e-DCC——把桥全部删除后剩下的每个连通块才是一个 e-DCC；但割点可以属于多个 v-DCC。
    4. 两个 v-DCC 至多只有一个公共点，且该公共点必为割点；除割点外，其他每个节点恰好属于 \(1\) 个 v-DCC。
    5. 每条边恰好属于 \(1\) 个 v-DCC；一条桥所"独占"的 v-DCC 恰由这条边的两个端点构成。

    12.3 判定定理¶

    定理

    • 一张无向连通图是点双连通图，当且仅当满足下列两个条件之一： 1. 图的顶点数不超过 \(2\)； 2. 图中任意两点都同时包含在至少一个简单环中。其中"简单环"指的是不自交的环，也就是我们通常画出的环。
    • 一张无向连通图是边双连通图，当且仅当任意一条边都包含在至少一个简单环中。

    证明（书中以点双连通图为例；边双连通图的情形可仿照完成）

    充分性：若任意两点 \(x, y\) 都同时包含在至少一个简单环中，则 \(x, y\) 之间至少有两条不相交的路径。无论从图中删除哪个节点，\(x, y\) 均能通过两条路径之一相连，故图中不存在割点。

    必要性：反证法。假设一张无向连通图是点双连通图，并且存在两点 \(x, y\)，它们不同时处于任何一个简单环中。

    • 如果 \(x, y\) 之间仅存在 \(1\) 条简单路径，那么路径上至少有一个割点，与"点双连通"矛盾。
    • 如果 \(x, y\) 之间存在 \(2\) 条或 \(2\) 条以上的简单路径，那么容易发现，任意两条都至少有一个除 \(x, y\) 之外的交点；进一步可推导出，\(x, y\) 之间的所有路径必定同时交于除 \(x, y\) 之外的某一点 \(p\)——不然就会存在两条没有交点的路径，形成一个简单环。根据定义，\(p\) 是一个割点，与"点双连通"矛盾。故假设不成立。证毕。

    12.4 v-DCC 算法依赖的两条性质¶

    下面两条性质（OI Wiki）是 §14 算法正确性的基础：

    1. 两个点双至多只有一个公共点，且一定是割点。
    2. 一个点双在 DFS 搜索树中 \(dfn\) 值最小的点，一定是割点或树根。

    由性质 2 分类讨论：

    • 若该点是割点：它一定所属点双在搜索树中的"根"——因为一旦再包含它的父节点，割点判定条件仍然成立，与"极大"矛盾；
    • 若该点是树根：
    • 有两个及以上子树 → 它是割点；
    • 只有一个子树 → 它是某个点双的根；
    • 没有子树 → 孤立点，视作一个点双。

    这保证每个 v-DCC 都会在"割点判定条件成立"的时刻被完整弹出（见 §14.1）。

    13 边双连通分量（e-DCC）的求法¶

    13.1 算法¶

    e-DCC 的计算非常容易：只需求出无向图中所有的桥，把桥都删除后，无向图会分成若干个连通块，每一个连通块就是一个"边双连通分量"。

    在具体的程序实现中，一般先用 Tarjan 算法标记出所有的桥边；然后，再对整个无向图执行一次深度优先遍历（遍历的过程中不访问桥边），划分出每个连通块。下面的代码在上篇 §6 求桥程序的基础上，计算出数组 \(c\)，\(c[x]\) 表示节点 \(x\) 所属的"边双连通分量"的编号。

    13.2 参考程序¶

    int c[SIZE], dcc;

void dfs(int x) {
    c[x] = dcc;
    for (int i = head[x]; i; i = Next[i]) {
        int y = ver[i];
        if (c[y] || bridge[i]) continue;     // 已染色 或 是桥（两个方向都已标记），跳过
        dfs(y);
    }
}

// 以下代码片段加在上篇 §6 求桥程序的 main 函数中（tarjan 之后）
for (int i = 1; i <= n; i++)
    if (!c[i]) {
        ++dcc;
        dfs(i);
    }
printf("There are %d e-DCCs.\n", dcc);
for (int i = 1; i <= n; i++)
    printf("%d belongs to DCC %d.\n", i, c[i]);

    复杂度：在 Tarjan 求桥的 \(O(N + M)\) 之上只多了一次线性 DFS，总时间复杂度仍为 \(O(N + M)\)。

    13.3 e-DCC 的缩点¶

    把每个 e-DCC 看作一个节点，把桥边 \((x, y)\) 看作连接编号为 \(c[x]\) 和 \(c[y]\) 的 e-DCC 对应节点的无向边，会产生一棵树（若原来的无向图不连通，则产生森林）。这种把 e-DCC 收缩为一个节点的方法就称为缩点。

    下面的代码在 Tarjan 求桥、求 e-DCC 的参考程序基础上，把 e-DCC 缩点，构成一棵新的树（或森林），存储在另一个邻接表中：

    int hc[SIZE], vc[SIZE * 2], nc[SIZE * 2], tc;

void add_c(int x, int y) {
    vc[++tc] = y, nc[tc] = hc[x], hc[x] = tc;
}

// 以下代码片段加在 main 函数中（求出 e-DCC 之后）
tc = 1;
for (int i = 2; i <= tot; i++) {             // 枚举每条有向边的存储下标
    int x = ver[i ^ 1], y = ver[i];          // 还原这条边的两个端点
    if (c[x] == c[y]) continue;              // 同一个 e-DCC 内部的边，跳过
    add_c(c[x], c[y]);
}
printf("缩点之后的森林，点数%d, 边数%d（可能有重边）\n", dcc, tc / 2);
for (int i = 2; i < tc; i += 2)
    printf("%d %d\n", vc[i ^ 1], vc[i]);

    要点：

    • 缩点后的图是一棵树 / 森林，且可能有重边——同一对 e-DCC 之间可能有多条桥，必要时需要去重。
    • 枚举 \(i = 2 \sim tot\) 时，每条无向边的两个方向各执行一次 add_c，恰好按成对变换存储；输出时只枚举偶数下标即可。
    • 这棵"桥树"是解决许多无向图问题的基础：树上的每条边对应原图的一条桥，配合倍增 LCA 等技术可以回答"两点之间必经边"类询问。

    14 点双连通分量（v-DCC）的求法¶

    14.1 算法：在 Tarjan 过程中维护一个栈¶

    为了求出"点双连通分量"，需要在 Tarjan 算法的过程中维护一个栈，并按照如下方法维护栈中的元素：

    1. 当一个节点第一次被访问时，把该节点入栈；
    2. 当割点判定法则中的条件 \(dfn[x] \le low[y]\) 成立时，无论 \(x\) 是否为根，都要：
    3. 从栈顶不断弹出节点，直至节点 \(y\) 被弹出；
    4. 刚才弹出的所有节点与节点 \(x\) 一起构成一个 v-DCC。

    为什么"无论 \(x\) 是否为根"都要弹栈？

    • 对非根节点 \(x\)：\(dfn[x] \le low[y]\) 成立意味着 \(subtree(y)\) 与上方只能通过 \(x\) 相连，此刻栈中从 \(y\) 往上的部分加上 \(x\) 恰是一个极大点双；
    • 对根节点 \(x\)：\(dfn[x]\) 是全树最小的时间戳，它的每个子节点 \(y\) 都满足 \(low[y] \ge dfn[x]\)，因此每个子树分支都会触发一次弹栈，弹出的部分加上 \(x\) 恰是一个 v-DCC。

    这与 §12.4 的性质 2 呼应：每个 v-DCC 在搜索树中 \(dfn\) 最小的点是割点或根，它恰好在边界条件成立的那一刻被完整弹出，且每个 v-DCC 只会被弹出一次。

    孤立点：若某个节点为孤立点（是根且没有出边），则它自己单独构成一个 v-DCC，需要特判。

    14.2 参考程序¶

    下面的程序在求出割点的同时，计算出 vector 数组 dcc，dcc[i] 保存编号为 \(i\) 的 v-DCC 中的所有节点：

    #include <bits/stdc++.h>
using namespace std;

const int SIZE = 100010;
int head[SIZE], ver[SIZE * 2], Next[SIZE * 2];
int dfn[SIZE], low[SIZE], stk[SIZE], top;    // stk：书中记作 stack，此处改名避免与 std::stack 混淆
int n, m, tot, num, root, cnt;
bool cut[SIZE];
vector<int> dcc[SIZE];                       // dcc[i]：编号为 i 的 v-DCC 中的所有节点

void add(int x, int y) {
    ver[++tot] = y, Next[tot] = head[x], head[x] = tot;
}

void tarjan(int x) {
    dfn[x] = low[x] = ++num;
    stk[++top] = x;                          // 规则 1：第一次被访问时入栈
    if (x == root && head[x] == 0) {         // 孤立点：自己单独构成一个 v-DCC
        dcc[++cnt].push_back(x);
        return;
    }
    int flag = 0;
    for (int i = head[x]; i; i = Next[i]) {
        int y = ver[i];
        if (!dfn[y]) {
            tarjan(y);
            low[x] = min(low[x], low[y]);
            if (low[y] >= dfn[x]) {
                flag++;
                if (x != root || flag > 1) cut[x] = true;
                cnt++;                       // 发现一个新的 v-DCC
                int z;
                do {
                    z = stk[top--];          // 规则 2：从栈顶弹出，直至 y 被弹出
                    dcc[cnt].push_back(z);
                } while (z != y);
                dcc[cnt].push_back(x);       // x 本身也属于该 v-DCC
            }
        }
        else low[x] = min(low[x], dfn[y]);
    }
}

int main() {
    scanf("%d%d", &n, &m);
    tot = 1;
    for (int i = 1; i <= m; i++) {
        int x, y;
        scanf("%d%d", &x, &y);
        if (x == y) continue;
        add(x, y), add(y, x);
    }
    for (int i = 1; i <= n; i++)             // 图不一定连通：搜索森林
        if (!dfn[i]) root = i, tarjan(i);
    for (int i = 1; i <= cnt; i++) {
        printf("v-DCC #%d:", i);
        for (int j = 0; j < (int)dcc[i].size(); j++)
            printf(" %d", dcc[i][j]);
        puts("");
    }
}

    正确性关键：节点 \(x\) 在弹出它的某个子树分支时自己并不出栈——dcc[cnt].push_back(x) 只是把 \(x\) 复制进该 v-DCC，\(x\) 仍留在栈中，因此 \(x\) 可以继续参与它所属的其他 v-DCC。这正是"割点可以属于多个 v-DCC"的实现基础。

    复杂度：每个节点恰好入栈、出栈各一次，时间复杂度 \(O(N + M)\)。

    14.3 v-DCC 的缩点（块割树）¶

    v-DCC 的缩点比 e-DCC 要复杂一些——因为一个割点可能属于多个 v-DCC。设图中共有 \(p\) 个割点和 \(t\) 个 v-DCC，建立一张包含 \(p + t\) 个节点的新图：把每个 v-DCC 和每个割点都作为新图中的节点，并在每个割点与包含它的所有 v-DCC 之间连边。容易发现，这张新图其实是一棵树（或森林），称为块割树（Block-Cut Tree）。

    // 给每个割点一个新的编号（编号从 cnt+1 开始）
num = cnt;
for (int i = 1; i <= n; i++)
    if (cut[i]) new_id[i] = ++num;

// 建新图，从每个 v-DCC 到它包含的所有割点连边
tc = 1;
for (int i = 1; i <= cnt; i++)
    for (int j = 0; j < (int)dcc[i].size(); j++) {
        int x = dcc[i][j];
        if (cut[x]) {
            add_c(i, new_id[x]);
            add_c(new_id[x], i);
        }
        else c[x] = i;                       // 除割点外，其他点仅属于 1 个 v-DCC
    }

printf("缩点之后的森林，点数 %d, 边数 %d\n", num, tc / 2);
printf("编号 1~%d 的为原图的 v-DCC，编号 >%d 的为原图割点\n", cnt, cnt);
for (int i = 2; i < tc; i += 2)
    printf("%d %d\n", vc[i ^ 1], vc[i]);

    要点：

    • 新图的节点数为 \(t + p\)：v-DCC 占用编号 \(1 \sim cnt\)，割点被重新编号为 \(cnt + 1 \sim num\)；
    • 若某个 v-DCC 含有 \(k\) 个割点，则它贡献 \(2k\) 条有向边；
    • 新图是树或森林，不存在环；
    • 块割树是回答"必经点"类问题的工具：原图中 \(u, v\) 之间路径必经的割点，恰为块割树上从 \(u\) 所属 v-DCC 到 \(v\) 所属 v-DCC 的路径经过的"割点节点"。

    15 本篇小结¶

    概念 判定 / 求法 归属与缩点
    e-DCC 求出所有桥 → 删桥后 DFS 染色（\(c[x]\)） 桥不属于任何 e-DCC；缩点得桥树（可能有重边）
    v-DCC Tarjan 中维护栈：\(dfn[x] \le low[y]\) 时弹栈至 \(y\)，弹出点 + \(x\) 构成一个 v-DCC 孤立点自成 v-DCC；割点可属于多个 v-DCC；与割点一起缩点得块割树

    两条最容易被混淆的事实：桥不属于任何 e-DCC，而割点可以属于多个 v-DCC；v-DCC 不等于"删去割点后剩余的连通块"。
