    B. 厄运数字¶

    赛时复盘：¶

    赛时很快想到 DP 状态设计和转移，用 \(g\) 和 \(f\) 两个数组来转移，具体方程见下文，赛时所有的样例都能过，但计算的时间复杂度比较几极限，在边缘，原以为至少有 50 分，却被卡常。 赛后发现，这道题的优化技巧很有用： - lowbit 优化转移 - bool 替换 unordered set

    特此记录

    题目描述¶

    小明和一群同学玩一个卡片排列游戏。

    小明手上有 \(n\) 张卡片，第 \(i\) 张卡片上写着一个「幸运数字」\(a_i\)。所有数字都是幸运数字。游戏开始后，小明需要把手中的卡片一张一张地按照某个顺序排列到桌上。当小明把手中所有卡片都排完（即手上不再有剩余卡片）的时候，游戏胜利。

    但是，存在一个由 \(m\) 个「厄运数字」组成的集合 \(B = \{b_1, b_2, \dots, b_m\}\)。在排列的过程中，任意一步只要已经排出的所有卡片数字之和（即前缀和）落到了某个厄运数字上，无论后续手上是否还有卡片、是否已经排完，都算失败。

    注意特别强调：哪怕小明把卡片全部排完（最后一步），只要最终累计和恰好是厄运数字，仍然算输。

    求所有让小明最终获胜的排列方案数，答案对 \(10^9 + 7\) 取模。

    题意抽象¶

    给定 \(n\) 个互不相同的「物品」，第 \(i\) 个物品的权值为 \(a_i\)。把全部 \(n\) 个物品排成一个全排列 \((p_1, p_2, \dots, p_n)\)，记前缀和

    \[ s_k = a_{p_1} + a_{p_2} + \dots + a_{p_k}, \quad k = 1, 2, \dots, n \]

    若存在 \(k\) 使得 \(s_k \in B\)，则该排列「失败」；否则「成功」。求成功排列数（\(\bmod\ (10^9 + 7)\)）。

    思路核心¶

    关键观察¶

    在已经排出的 \(k\) 张卡片下，前缀和 \(s_k\) 等于这 \(k\) 张卡片对应的 \(a_i\) 之和。

    更值得注意的是：这 \(k\) 张卡片到底是怎么挑出来的，与 \(s_k\) 没关系——只要知道「哪 \(k\) 张卡片已经被排出」（即一个 \(n\) 位 0/1 子集），\(s_k\) 就唯一确定了。

    因此可以把「按排列做 DP」转化成「按集合掩码做子集 DP」，状态数从 \(n!\) 暴降到 \(2^n\)。

    为什么「只看集合」就够¶

    排列过程是：每次从未用卡片里选一张加到末尾，逐步从 \(\varnothing\) 长到「全集」。这一条「构造路径」上经过的若干中间集合，恰好就是这个排列产生的前缀集合序列。检查前缀和是否踩中 \(B\)，等价于检查这条路径上每一步到达的集合对应的 \(g[\text{集合}]\) 都不在 \(B\) 中。

    如此一来，DP 状态只需要记录「当前已经排出的卡片集合」即可。

    状态设计¶

    记号 含义
    \(S\) \(n\) 位 0/1 掩码，第 \(i\) 位 = 1 表示第 \(i\) 张卡片已经被排出
    \(g[S]\) 集合 \(S\) 中所有 \(a_i\) 之和（用 lowbit 预计算，见下文）
    \(f[S]\) 让小明以集合 \(S\) 作为「当前已排出卡片集合」时，所有合法构造路径数
    full \((1 \ll n) - 1\)，全集掩码
    边界 \(f[0] = 1\)（空序列唯一）
    答案 \(f[\texttt{full}]\)

    状态含义的细读：「\(f[S]\) 统计的是把 \(S\) 中的卡片以某个顺序排到桌面上、整个过程中每一步前缀和都不落在 \(B\) 中的方案数」。当 \(m = 0\) 时退化到 \(f[S] = |S|!\)，因此答案等于 \(n!\)，与样例 1 吻合。

    状态转移¶

    按集合从小到大扩展。每一步从 \(S\) 选择一张还未用过的卡片 \(j\) 加入，得到新集合 \(S' = S \cup \{j\}\)。如果此时新的累计和 \(g[S']\) 不在 \(B\) 中，就把从 \(S\) 出发的方案数累加到 \(f[S']\)：

    \[ f[S'] \mathrel{+{=}} f[S] \cdot [\, g[S'] \notin B \,] \]

    等价地，也可以写成差分形式（更适合从大往小枚举）：

    \[ f[S] = [\, g[S] \notin B \,] \cdot \sum_{k \in S} f[S \setminus \{k\}] \]

    写成代码：

    f[0] = 1;
for (int S = 0; S <= full; S++) {
    for each card j not in S:
        int T = S | (1 << j);
        if (g[T] not in B)
            f[T] += f[S];
}

    算法层面时间复杂度：\(O(n \cdot 2^n)\)。每个状态有 \(n\) 个潜在转移方向。

    卡常 / lowbit 优化拆解¶

    题目真正的难度在「常数优化」上。当 \(n = 24\) 时总状态数 \(2^{24} \approx 1.6 \times 10^7\)，代码放在朴素写法上跑不满 1 秒就会被卡到 10 分。下面把赛时代码里能优化的三处逐一点出。

    卡常点 1：用 lowbit 把 \(g[\,]\) 的预计算从 \(O(n \cdot 2^n)\) 砍到 \(O(2^n)\)¶

    for (int stat = 1; stat < (1 << n); stat++) {
    int lb = stat & -stat;              // 取最低位的 1
    int id = __builtin_ctz(lb) + 1;     // ctz = count trailing zeros
    g[stat] = g[stat ^ lb] + a[id];     // 由去掉最低位的子集递推
}

    任何非零状态都可以用一次 lowbit 把它拆成「一个最低位 + 少掉这个位的子集」。这样一次加法就能递推出 \(g[\text{stat}]\)，比「枚举每个 \(j\)、检查 \(j\) 是否在 stat 中」少走 \(n\) 路分支。

    卡常点 2：枚举「未使用位」取代「扫描全部 \(n\) 位」¶

    int left = full ^ stat;          // 未使用的卡片位集合
while (left) {
    int lb  = left & -left;
    int nxt = stat | lb;
    // ... 检查 + 累加 f[nxt]
    left -= lb;
}

    left 本身就是「可用位的集合」，循环次数严格等于 \(n - \text{popcount}(\text{stat})\)，是赛时版本「for j in 1..n, if (stat & bit) skip」循环次数的一半，且少一次「bit & stat」的判断和一次 continue。

    卡常点 3：用 bool bad[] 替 unordered_set<int>¶

    \(m \le 2\)，而 \(g[\,]\) 最大值 \(\le 24 \times 1024 = 24576\)，直接开

    bool bad[25005];

    下标定位即可，比 unordered_set<int>::find() 走哈希桶的常数小一个数量级。这条建议在所有「状态数很大、查询极热」的题中都能复用。

    时间 / 空间复杂度¶

    维度 量
    时间 \(O(n \cdot 2^n)\)，\(n = 24\) 时约 \(4 \times 10^8\) 次基本操作，三处优化落地后 1 s 测速可过
    空间 \(O(2^n)\)，g[(1<<24)] 与 f[(1<<24)] 各占 \(64\) MB，合计 \(128\) MB，题目给的 \(256\) MB 上限卡得住

    赛时 TLE 代码（10 分）¶

    #include <bits/stdc++.h>
using namespace std;

const int N = 24;
const int MOD = 1e9 + 7;

int n, m;
int a[N + 1];
int b[N + 1];

unordered_set<int> flag;

int g[(1 << N)], f[(1 << N)];

int main() {
    freopen("misfortune.in",  "r",  stdin);
    freopen("misfortune.out", "w", stdout);

    ios::sync_with_stdio(false);
    cin.tie(0);

    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];

    cin >> m;
    for (int i = 1; i <= m; i++) {
        cin >> b[i];
        flag.insert(b[i]);
    }

    for (int stat = 0; stat < (1 << n); stat++) {
        for (int j = 1; j <= n; j++) {
            if ((1 << (j - 1)) & stat)
                g[stat] += a[j];
        }
    }

    f[0] = 1;

    for (int stat = 0; stat < (1 << n); stat++) {
        for (int j = 1; j <= n; j++) {
            if ((1 << (j - 1)) & stat)
                continue;

            if (flag.find(g[stat | (1 << (j - 1))]) == flag.end()) {
                f[stat | (1 << (j - 1))] =
                    (f[stat | (1 << (j - 1))] + f[stat]) % MOD;
            }
        }
    }

    cout << f[(1 << n) - 1] % MOD << '\n';

    return 0;
}

    为什么 TLE（10 分）

    1. 计算 \(g[\,]\) 时每个 stat 都遍历全部 \(n\) 位、常数远大于 lowbit 写法；
    2. 状态转移时 for j in 1..n + 位运算 skip 已用位 也是 \(O(n \cdot 2^n)\) 的常数，但每一步都走全 \(n\) 路分支；
    3. unordered_set<int>::find() 在 \(10^8\) 级别的调用下哈希冲突和可能的 rehash 是贵的；用 bool 数组直接下标定位即可。

    算法本体没问题，全部都是常数优化没到位。

    赛后 AC 代码（100 分）¶

    #include <bits/stdc++.h>
using namespace std;

const int N = 24;
const int MOD = 1e9 + 7;

int n, m;
int a[N + 1];

int g[(1 << N)], f[(1 << N)];

bool bad[25005];

int main () {
    freopen("misfortune.in",  "r",  stdin);
    freopen("misfortune.out", "w", stdout);

    ios::sync_with_stdio(false);
    cin.tie(0);

    cin >> n;
    for (int i = 1; i <= n; i ++) cin >> a[i];

    cin >> m;
    for (int i = 1; i <= m; i ++) {
        int val;
        cin >> val;
        if (val < 25005) bad[val] = true;
    }

    for (int stat = 1; stat < (1 << n); stat ++) {
        int lb = stat & -stat;
        int id = __builtin_ctz(lb) + 1;
        g[stat] = g[stat ^ lb] + a[id];
    }

    f[0] = 1;
    int full = (1 << n) - 1;

    for (int stat = 0; stat <= full; stat ++) {
        int left = full ^ stat;
        while (left) {
            int lb = left & -left;
            int nxt_stat = stat | lb;

            if (!bad[g[nxt_stat]]) {
                f[nxt_stat] += f[stat];
                if (f[nxt_stat] >= MOD) f[nxt_stat] -= MOD;
            }
            left -= lb;
        }
    }

    cout << f[full] % MOD << '\n';

    return 0;
}

    改动对照

    位置 赛时写法（10 分） 赛后写法（100 分） 效果
    g[] 预计算 双重循环 \(O(n \cdot 2^n)\) lowbit 递推 \(O(2^n)\) 常数砍掉 \(n/2\) 量级
    状态转移内层 for j in 1..n + continue left = full ^ stat; while(left) 枚举可用位 循环次数直接减半
    厄运数字查表 unordered_set<int>::find bool bad[25005] 下标 一次访问代替整段哈希

    复盘¶

    • 这道题算法本体（集合掩码 DP）非常朴素，赛时没有想到的是 \(n = 24\) 这种「刚到上限」的数据规模对常数极度敏感。
    • 10 分到 100 分的关键不是换算法，而是 用 lowbit + 下标数组优化常数：
      1. g[] 预计算由 \(O(n \cdot 2^n)\) 降到 \(O(2^n)\)；
      2. 状态转移只枚举未使用位，少走 \(n\) 路分支；
      3. 查询厄运数字从哈希容器换成下标数组。
