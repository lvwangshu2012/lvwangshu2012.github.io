    P3029 USACO11NOV Cow Lineup S——滑动窗口收缩顺序的致命细节¶

    P3029 [USACO11NOV] Cow Lineup S 题解——滑动窗口收缩顺序的致命细节¶

    题目链接¶

    P3029 [USACO11NOV] Cow Lineup S

    题目描述¶

    有 \(N\) 头奶牛，每头牛有一个位置坐标 \(x\) 和一个品种 ID。约翰想要拍摄一段连续区间的照片（按坐标排序后连续），使得该区间内包含所有不同品种的奶牛。照片成本等于区间右端点坐标减去左端点坐标。求最小成本。

    赛时错误代码（75分）¶

    deque<ll> q;
ll ans = INF;

for (int i = 1; i <= n; i++) {
    // ① 收缩左端
    while (!q.empty() && mp[a[q.front()].id] > 1) {
        mp[a[q.front()].id]--;
        q.pop_front();
    }

    // ② 更新答案
    if (cnt == m) ans = min(ans, a[q.back()].x - a[q.front()].x);

    // ③ 收缩右端
    while (!q.empty() && mp[a[q.back()].id] > 1) {
        mp[a[q.back()].id]--;
        q.pop_back();
    }

    // ④ 加入当前牛
    if (mp[a[i].id] == 0) cnt++;
    mp[a[i].id]++;
    q.push_back(i);
}
cout << ans << '\n';

    错误本质剖析¶

    我最初以为错误是“漏掉了以最后一头牛为右端点的窗口”，但经过学长讲解，发现根本问题在于窗口收缩逻辑错误，导致更新答案时窗口不是最紧的，甚至左右端点关系被破坏（左端点“超过”右端点）。

    1. 右端收缩是多余的，且破坏窗口的紧凑性¶

    在滑动窗口中，右端点由循环变量 i 自然固定，我们只需要收缩左端，移除左边多余的品种。而原代码中同时收缩右端（步骤③），试图移除右边多余的品种，但这一步在更新答案之后，导致更新答案时，窗口可能还包含右端冗余元素，计算出的窗口长度并非当前状态下的最小值。更糟的是，右端收缩并不能彻底移除所有冗余（例如冗余出现在队列中间时无法通过弹出队尾去除），使得窗口状态混乱。

    2. 更新答案时左右端点可能处于“错位”状态¶

    在步骤②更新答案时，左端已经收缩过（步骤①），而右端尚未收缩（步骤③）。此时左右端点的选取标准不一致：左端是最紧的，右端却是宽松的。这种不对称导致计算出的窗口长度可能偏大，而实际最优解需要在右端也收缩后才能得到。由于更新时机错过，最优解被漏掉。

    更隐蔽的是，在某些边界情况下（例如窗口内品种计数 cnt == m，但队列由于之前的收缩操作可能为空），访问 q.front() 和 q.back() 时队列为空，产生未定义行为，表现为“左端点超过右端点”的错误。

    3. 循环结束后没有补处理¶

    当 i = n 时，最后一头牛加入后循环直接结束，没有机会再次收缩和更新答案。若最优窗口右端点恰为最后一头牛，则答案错误。

    正确解法¶

    采用标准滑动窗口模板：只收缩左端，右端由循环变量固定。

    #include <bits/stdc++.h>
using namespace std;
using ll = long long;
const int N = 50005;
const ll INF = 1e18;

struct Cow {
    ll x, id;
} a[N];

bool cmp(Cow a, Cow b) { return a.x < b.x; }

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i].x >> a[i].id;

    sort(a + 1, a + n + 1, cmp);

    // 统计品种总数
    unordered_set<ll> st;
    for (int i = 1; i <= n; i++) st.insert(a[i].id);
    int m = st.size();

    map<ll, int> mp;
    int cnt = 0;
    ll ans = INF;

    int l = 1;
    for (int r = 1; r <= n; r++) {
        // 加入右端点
        if (mp[a[r].id] == 0) cnt++;
        mp[a[r].id]++;

        // 收缩左端点（移除多余品种）
        while (l <= r && mp[a[l].id] > 1) {
            mp[a[l].id]--;
            l++;
        }

        // 更新答案
        if (cnt == m) ans = min(ans, a[r].x - a[l].x);
    }

    cout << ans << '\n';
    return 0;
}

    为什么这样写是正确的？¶

    • 每次循环，右指针 r 固定，窗口右端点就是当前牛。
    • 收缩左端后，窗口内的品种计数仍然是 cnt（因为只移除了重复品种），且窗口左端已经尽可能靠右，窗口长度达到以 r 为右端点时的最小值。
    • 更新答案时，窗口一定是合法的、最紧的，左右端点关系恒有 l <= r。
    • 循环覆盖了所有可能的右端点，不会漏掉任何最优解。

    总结与教训¶

    1. 滑动窗口不要随意收缩右端。右端由循环变量自然控制，收缩右端会破坏窗口的时序和紧凑性，极易造成漏解。
    2. 更新答案前必须确保窗口完全收缩。若先更新后收缩，可能得到偏大的答案。
    3. 警惕双端队列的错误用法。如果使用双端队列模拟窗口，操作顺序必须严格，否则容易出现队列为空、指针越界等未定义行为。
    4. 赛场上推荐使用两个整数指针 l, r 来实现滑动窗口，逻辑清晰，不易出错。
